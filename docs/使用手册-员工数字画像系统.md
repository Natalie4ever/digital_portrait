## 一、账号与登录

### 1.1 登录方式

**API 端点：** `POST /api/auth/login`

```json
// 请求
{ "ehr_no": "0000001", "password": "1234567" }

// 响应
{ "access_token": "eyJ...", "token_type": "bearer", "expire_minutes": 60 }
```

**后续请求携带 Token：**
```
Authorization: Bearer <access_token>
```

### 1.2 忘记密码

普通员工忘记密码需联系管理员重置。管理员可调用：

`POST /api/admin/users/reset-password`

```json
{ "ehr_no": "1234567", "new_password": "1234567" }
```

### 1.3 修改密码（本人）

`POST /api/auth/change-password`

```json
{ "old_password": "1234567", "new_password": "newpassword" }
```

## 三、个人档案管理

### 3.1 查看我的档案

`GET /api/profile/me`

返回完整档案，包含 13 个子模块：
- **base** — 基础信息（性别、民族、职位等）
- **political** — 政治面貌
- **education** — 学历学位
- **family** — 家庭关系
- **resume** — 工作简历
- **reward** — 奖惩记录
- **qualification** — 外部资格证书（含有效期 `valid_until`）
- **achievement** — 专业成果
- **language** — 语言能力
- **contact** — 通讯信息（电话、通勤时间等）
- **skill_tags** — 个人技能标签
- **development_intent** — 发展意向（Step 1 新增）
- **project_summaries** — 项目总结（Step 1 新增）

### 3.2 编辑各类信息

所有子模块均支持 **增 / 改 / 删** 操作，以下以政治面貌为例：

```bash
# 新增
POST /api/profile/me/political
{ "political_status": "群众", "join_date": "2020-01-01", "introducer": "张三" }

# 修改
PUT /api/profile/me/political/{id}
{ "political_status": "共青团员" }

# 删除
DELETE /api/profile/me/political/{id}
```

### 3.3 通讯信息（单条）

`PUT /api/profile/me/contact`

```json
{
  "phone": "13800000000",
  "emergency_contact": "张三",
  "emergency_phone": "13900000000",
  "commute_minutes": 25,
  "home_address": "北京市朝阳区..."
}
```

> `commute_minutes`（通勤时间）用于应急场景筛选和团队能力分析。

### 3.4 技能标签

```bash
# 添加标签
POST /api/profile/me/skill-tags
{ "tag_name": "Python", "template_id": 1 }

# 删除标签
DELETE /api/profile/me/skill-tags/{id}
```

### 3.5 发展意向（Step 1 新增）

`PUT /api/profile/me/development-intent`

```json
{
  "development_path": "管理发展路径",
  "short_term_goal": "1年内考取 PMP 认证",
  "mid_term_goal": "3年内晋升为主管",
  "core_abilities": ["沟通与影响力", "团队管理"],
  "learning_methods": ["外部认证课程", "内部导师制"],
  "learning_courses": "项目管理、领导力",
  "rotation_interest": "是",
```

### 3.6 项目总结（Step 1 新增）

## 四、管理员功能

### 4.1 用户管理

#### 4.1.1 用户列表

`GET /api/admin/users`

支持筛选：`group_name`、`role`、`is_emergency_staff`、`include_disabled`

#### 4.1.2 创建用户

`POST /api/admin/users`

```json
{
  "ehr_no": "9990001",
  "name": "张三",
  "group_name": "测试组",
  "role": "user",
  "initial_password": "1234567"
}
```

#### 4.1.3 编辑用户

`PUT /api/admin/users/{ehr_no}`

可修改：姓名、角色、组别（调组会记录历史）、是否禁用

#### 4.1.4 软删除用户

`DELETE /api/admin/users/{ehr_no}`

软删除后该账号无法登录，日志可追溯。

#### 4.1.5 切换应急先锋队（Step 1 新增）

`POST /api/admin/users/{ehr_no}/toggle-emergency`

```bash
# 切换某员工的应急先锋队标识
# 返回 { "ehr_no": "1234567", "is_emergency_staff": true }
```

> 仅管理员可操作。切换后自动记录操作日志。

#### 4.1.6 批量导入用户

`POST /api/admin/users/batch-import`

上传 Excel 文件（.xlsx），表头需包含：姓名、ehr号、组别

### 4.2 档案管理

#### 4.2.1 查看他人档案

`GET /api/profile/by-ehr/{ehr_no}`

管理员可查看任意员工档案；组长只能查看本组成员。

#### 4.2.2 档案列表（多条件筛选）

`GET /api/profile/admin/list`

支持按：组别、角色、是否应急先锋队、技能标签、通勤时间筛选

#### 4.2.3 更新他人基础信息（仅限管理员）

`PUT /api/profile/by-ehr/{ehr_no}/base`

### 4.3 组员调换（Step 2 新增）

#### 4.3.1 调组

`POST /api/admin/group-transfers/transfer`

```json
{
  "ehr_no": "1234568",
  "to_group": "测试二组",
  "reason": "工作需要",
  "remark": "试用期结束后转组"
}
```

调组后：
- `user.group_name` 立即更新
- `group_transfer_history` 写入一条新记录（`leave_date = NULL` 表示当前组）
- 原记录的 `leave_date` 被填上
- 操作日志记录

#### 4.3.2 调组历史列表

`GET /api/admin/group-transfers`

支持按员工姓名、EHR、源组、目标组筛选

#### 4.3.3 单员工调组历史

`GET /api/admin/group-transfers/user/{ehr_no}`

返回该员工历次调组记录。

#### 4.3.4 查询全部组别

`GET /api/admin/group-transfers/groups`

返回系统中所有现存组别名称列表。

### 4.4 操作日志

`GET /api/admin/operation-logs`

记录所有写操作（登录、增删改、调组、切换应急标识等）。

支持按 `user_id` 和 `action` 模糊筛选。

`PUT /api/home-visits/{id}`

`DELETE /api/home-visits/{id}`

管理员可删除任意记录；组长可删除本组记录。

#### 5.1.4 家访记录列表

`GET /api/home-visits`

- 管理员：查看全部
- 组长：查看本组所有成员的家访记录

## 六、智能筛选四大场景（Step 3 新增）

### 6.1 应急响应场景

查找通勤时间短的非应急先锋队员（优先调用）

```json
{
  "scenario": "emergency",
  "max_commute_minutes": 60
}
```

返回按 `is_emergency_staff` 降序 + `commute_minutes` 升序排列

### 6.2 活动选人场景

按兴趣标签匹配员工（OR 匹配）

```json
{
  "scenario": "activity",
  "interest_tags": ["舞蹈", "主持"]
}
```

匹配度 = 命中标签数 × 20（封顶 100）

### 6.3 项目组队场景

按必选技能、证书数、项目数多维筛选

```json
{
  "scenario": "project",
  "required_skill_tags": ["Python", "数据分析"],
  "min_cert_count": 1,
  "min_project_count": 1,
  "max_commute_minutes": 60
}
```

评分规则：

| 条件 | 加分 |
|------|------|
| 每命中一个必选技能 | +30 |
| 证书数 ≥ min_cert_count | +20 |
| 项目数 ≥ min_project_count | +20 |
| 通勤时间 < 60分钟 | +10 |

### 6.4 人员调配场景

排除指定组别，按多维评分推荐

```json
{
  "scenario": "transfer",
  "target_group": "待调配组",
  "max_commute_minutes": 60
}
```

评分规则：

| 条件 | 加分 |
|------|------|
| 每持有1个技能标签 | +5（封顶40） |
| 是应急先锋队员 | +20 |
| 通勤 < 30分钟 | +30 |
| 通勤 30-60分钟 | +15 |

### 6.5 导出 Excel

`POST /api/admin/scenarios/export`

使用与 search 相同的条件，导出 Excel 文件，包含：EHR号、姓名、组别、是否应急、通勤时间、技能标签、匹配度等。

## 七、团队能力分析（Step 4 新增）

### 7.1 综合概览

`POST /api/admin/analytics/overview`

返回：技能分布（每项技能的掌握者列表）、组别人数与应急人数

### 7.2 证书统计

`POST /api/admin/analytics/certificates`

按证书类型统计持有人数和具体人员列表

### 7.3 风险预警

`POST /api/admin/analytics/risks`

风险判定规则：

| 风险类型 | 阈值 |
|---------|------|
| 技能「仅1人」掌握 | 🔴 红色 |
| 技能「2-3人」掌握 | 🟡 黄色 |
| 技能「4人及以上」 | 🟢 绿色 |
| 应急先锋队 < 3人 | 🔴 红色 |
| 应急先锋队 3-5人 | 🟡 黄色 |
| 应急先锋队 ≥ 5人 | 🟢 绿色 |

### 7.4 应急先锋队通勤分布

`POST /api/admin/analytics/emergency`

统计应急先锋队通勤时间分布：
- < 30分钟
- 30-60分钟
- > 60分钟
- 未设置

同时返回覆盖率（应急队员/全员总数）

### 7.5 综合导出

`POST /api/admin/analytics/export`

导出包含 4 个 Sheet 的 Excel：
1. **能力分布** — 技能分布 + 组别密度
2. **证书统计** — 各证书持有情况
3. **风险预警** — 红黄绿风险项详情
4. **应急能力** — 通勤分布 + 覆盖率

## 十二、常见问题

**Q: 普通员工能否新建家访记录？**
> 不能。家访记录只能由组长创建，普通员工可查看自己的家访记录。

**Q: 管理员能否编辑家访记录？**
> 不能。管理员只能查看和删除家访记录，编辑权限归组长所有。

**Q: 组长调组后原成员还能查看吗？**
> 调组后，组长的"本组"范围更新，原成员移出组长视野，**历史家访记录仍保留**但不可再新建。

**Q: 应急先锋队标识有什么用？**
> 用于应急响应场景筛选。系统会优先推荐非应急先锋队且通勤时间短的员工作为应急补充力量。

**Q: 发展意向的数组字段如何存储？**
> `core_abilities`、`learning_methods`、`project_interests` 等多选字段以 JSON 字符串形式存储到数据库。

**Q: 软删除和物理删除有什么区别？**
> 系统使用软删除（设置 `deleted_at` 时间戳），数据可恢复但不影响业务查询。物理删除仅在测试清理时使用。
